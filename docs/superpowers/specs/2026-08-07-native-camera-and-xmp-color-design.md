# LUME 네이티브 카메라와 XMP 색 재현 설계

## 목표

기존 WebView 카메라 프로토타입을 Android 네이티브 카메라 앱으로 교체한다. 1차 기준 기기는 Galaxy S26 Ultra이며, 끊김 없는 필터 프리뷰, 필터 적용 4K 30fps 영상, 최대 해상도 사진, 실제 렌즈 전환과 줌, XMP 가져오기·수정·저장을 제공한다.

라이트룸과 완전히 같은 결과를 약속하지는 않는다. 대신 지원하는 XMP 항목은 정해진 색관리 파이프라인에서 일관되게 처리하고, 지원하지 않는 Adobe 전용 항목은 사용자에게 숨기지 않고 표시한다.

## 범위

### 1차 버전에 포함

- Kotlin 기반 Android 네이티브 앱
- CameraX를 기본 촬영 계층으로 사용하고 필요한 기능만 Camera2 interop으로 보완
- 기기의 실제 카메라 ID, 물리 렌즈, 해상도, 프레임률, 코덱 능력 조회
- 초광각, 광각, 3배, 5배 렌즈 선택과 지원 범위 내 연속 줌
- 필터 적용 4K 30fps 영상 촬영
- 지원되는 기기 조합에서 4K 60/120fps 노출
- 센서와 촬영 세션이 허용하는 최대 해상도 JPEG 사진
- 8K 30fps 원본 영상 촬영 후 프리셋 적용 내보내기
- XMP 가져오기, 지원 여부 분석, 편집, 앱 프리셋 저장, XMP 내보내기
- 기존 트렌드 LOOK, 미스트, 크로스, 색상 필터, Digital ND 이전
- 프레임 드롭, 발열, 저장 공간, 미지원 조합을 사용자에게 명확히 표시

### 1차 버전에서 제외

- 8K 실시간 필터 녹화 보장
- Adobe Camera Raw의 비공개 카메라 프로파일과 동일한 렌더링
- Adobe AI 마스크, 피사체/하늘 선택, 생성형 기능
- 모든 Android 기기에서 동일한 렌즈 이름과 최대 촬영 조합 보장
- 광학 ND와 동일한 효과 보장
- iOS 구현과 커뮤니티·결제 기능

## 핵심 원칙

1. 앱이 해상도나 프레임률을 임의로 낮추지 않는다. 요청한 조합을 지원하지 않으면 가능한 조합과 이유를 표시한다.
2. 프리뷰와 영상 저장은 동일한 GPU 색 파이프라인을 사용한다.
3. 고해상도 사진은 프리뷰 캔버스를 확대하지 않고 원본 캡처를 별도로 렌더링한다.
4. 8K는 품질과 안정성을 위해 원본 촬영 후 오프라인 렌더링한다.
5. XMP 파싱, 색 처리, 카메라 제어, UI를 독립 모듈로 분리한다.

## 아키텍처

### 앱 셸과 UI

Jetpack Compose로 카메라 화면, 촬영 설정, 프리셋 브라우저, XMP 호환성 화면을 구성한다. 기존 LUME의 어두운 카메라 UI와 LOOK/LENS/ND 조작 체계를 유지하되 Lightroom의 상표·아이콘·고유 화면을 직접 복제하지 않는다.

### 카메라 계층

`CameraCapabilityRepository`가 CameraX와 Camera2 특성을 읽어 렌즈, 논리/물리 카메라, 줌 범위, 지원 화질과 FPS를 앱 모델로 변환한다. `CameraSessionController`는 Preview, ImageCapture, VideoCapture를 수명주기에 맞게 결합한다.

기본 경로는 CameraX이다. CameraX가 물리 렌즈 선택이나 고속 촬영 조합을 충분히 노출하지 않는 경우에만 Camera2 interop을 사용한다. 특정 배율을 디지털 줌으로 가장하지 않고, 현재 물리 렌즈와 디지털 크롭 여부를 UI에 구분해 표시한다.

### 실시간 GPU 효과

`LumeSurfaceProcessor`가 CameraEffect의 Preview와 VideoCapture 대상 프레임을 OpenGL ES 3.x로 처리한다. 프리뷰는 화면 해상도에 맞추고, 저장 파이프라인은 선택한 영상 화질을 유지한다. 셰이더는 색 변환 패스와 광학 효과 패스를 분리하며, 미스트처럼 여러 샘플이 필요한 효과는 품질 단계별 탭 수를 제한한다.

성능 계측기는 렌더 시간, 실제 출력 FPS, 누락 프레임, 열 상태를 기록한다. 4K 30fps에서 지속적으로 프레임 예산을 넘으면 녹화를 강행하지 않고 어떤 효과가 병목인지 알려준다.

### 사진 처리

ImageCapture가 제공하는 최대 품질 원본을 받아 별도 워커에서 색 변환한다. 미리보기 해상도의 Canvas를 확대하지 않는다. 원본과 보정본을 선택적으로 저장하고 EXIF 방향, 촬영 시각, 렌즈 정보를 보존한다.

### 8K 처리

8K 30fps는 기기 capability 조회에서 실제 지원될 때만 노출한다. 원본 영상은 기기의 하드웨어 인코더로 직접 저장한다. 촬영 후 사용자가 내보내기를 선택하면 프레임을 디코딩해 GPU 색 파이프라인을 적용하고 지원 가능한 코덱과 비트레이트로 다시 인코딩한다. 저장 공간과 예상 처리 시간을 시작 전에 표시한다.

## XMP 색관리

### 파싱과 호환성

XMP 값을 `LumePreset`이라는 정규화 모델로 변환한다. 각 필드는 `supported`, `approximated`, `unsupported` 중 하나의 상태를 갖는다. Camera Raw 프로파일, LookTable, 로컬 마스크처럼 재현할 수 없는 항목은 무시하지 않고 호환성 보고서에 표시한다.

### 처리 순서

색 파이프라인은 다음 순서를 고정한다.

1. 입력 YUV를 선형 RGB 작업 공간으로 변환
2. 화이트밸런스와 틴트
3. 노출
4. 하이라이트, 섀도, 화이트, 블랙과 기본 대비
5. RGB 합성 톤커브와 채널별 커브
6. HSL 8색의 색상, 채도, 명도
7. 비브런스와 전체 채도
8. 컬러 그레이딩과 디헤이즈·클래리티 근사
9. 미스트, 크로스, 색상 필터, Digital ND
10. 디스플레이 또는 저장 색공간으로 변환하고 디더링

숫자 범위를 단순 비례 변환하지 않는다. 각 조정은 기준 이미지와 수치 샘플을 이용해 별도의 전달 함수로 보정한다.

### 비교 도구

같은 기준 JPEG 또는 DNG와 XMP를 라이트룸에서 내보낸 참조 이미지와 LUME 결과에 적용해 나란히 비교한다. 평균 색차만으로 판단하지 않고 회색축, 피부톤, 하늘색, 녹색, 하이라이트 롤오프, 그림자 색편향을 각각 확인한다. 사용자는 분할선으로 두 이미지를 비교하고 차이가 큰 조정 항목을 볼 수 있다.

## 오류와 폴백

- 요청한 렌즈·해상도·FPS 조합이 없으면 지원되는 가장 가까운 목록을 제시하고 사용자가 선택하게 한다.
- 녹화 중 열 상태가 심각해지면 경고하고 안전 종료한다. 해상도를 몰래 변경하지 않는다.
- XMP가 손상됐거나 필수 값이 잘못되면 가져오기를 중단하고 문제 필드를 표시한다.
- 효과 프로세서가 초기화되지 않으면 원본 촬영 모드만 제공하고 원인을 기록한다.
- 저장 공간이 예상 파일 크기보다 부족하면 녹화를 시작하지 않는다.

## 테스트와 완료 기준

### 자동 테스트

- XMP fixture별 파싱, 정규화, 내보내기 왕복 테스트
- 지원·근사·미지원 필드 분류 테스트
- 톤커브, HSL, 노출 전달 함수의 골든 이미지 테스트
- 카메라 capability 조합 선택 테스트
- 해상도·FPS가 묵시적으로 하향되지 않는 정책 테스트
- 셰이더 컴파일 및 대표 프레임 렌더 테스트

### S26 Ultra 실기기 기준

- 필터 프리뷰가 장시간 촬영에서도 사용하기 어려운 수준으로 끊기지 않는다.
- 필터 적용 4K 30fps 영상이 요청한 해상도와 프레임률로 저장된다.
- 최대 해상도 사진은 프리뷰 확대본이 아닌 ImageCapture 원본에서 생성된다.
- 초광각, 1배, 3배, 5배 렌즈가 기기 보고값과 일치한다.
- 연속 줌과 렌즈 전환 시 앱이 중단되지 않는다.
- 8K 30fps 원본 촬영과 촬영 후 프리셋 내보내기가 동작한다.
- XMP 비교 화면에서 지원하지 않는 항목과 주요 색 차이를 확인할 수 있다.

## 단계적 전달

1. 네이티브 프로젝트와 capability 진단 화면
2. 무필터 고화질 사진·4K 영상·렌즈·줌
3. GPU 프리뷰와 필터 적용 4K 30fps
4. XMP 정규화 모델과 색차 비교 도구
5. 고해상도 사진 렌더와 8K 후처리
6. 성능·발열 튜닝과 설치용 프리뷰 APK

각 단계는 S26 Ultra에서 확인 가능한 APK를 만든 뒤 다음 단계로 진행한다.
