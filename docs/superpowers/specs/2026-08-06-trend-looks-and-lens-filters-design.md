# LUME 트렌드 룩·렌즈 필터·프리셋 편집 설계

## 목표

LUME 웹 프로토타입에서 사용자가 Lightroom XMP 프리셋을 가져와 실시간 카메라에 적용하고, 색을 수정해 앱 내부 또는 XMP로 저장하며, 트렌드 룩과 디지털 렌즈 필터를 사진과 영상에 동일하게 적용할 수 있게 한다.

이번 단계는 Android 네이티브 최대 화질 엔진을 만들기 전의 모바일 색감·편집 UX 검증 단계다. 배포된 GitHub Pages 주소에서 Android Chrome으로 확인할 수 있어야 한다.

## 범위

### 포함

- XMP 가져오기, 지원 여부 분석, 실시간 적용
- 기존 사용자 프리셋 덮어쓰기 및 새 프리셋 저장
- 내장 프리셋 수정 시 사용자 복사본 자동 생성
- XMP 내보내기 및 재가져오기 값 일치 검증
- 원본 XMP 보존과 편집 버전 관리
- 트렌드 내장 룩 10종
- Black Mist, White Mist, Cross, 색상 필터
- 창작용 Digital ND
- 룩과 필터 조합 저장
- 사진과 영상에 같은 렌더링 파이프라인 적용
- 모바일 UI 및 GitHub Pages 실기기 검증

### 제외

- Adobe 비공개 현상 엔진과 픽셀 단위 동일성
- Adobe AI 마스크 및 Adaptive Preset 재현
- 실제 광학 ND와 동일한 노출 제어
- Computational ND 장노출 합성
- Android 네이티브 CameraX/Camera2 최대 해상도 구현
- 커뮤니티, 결제, 프리셋 판매 백엔드

## 제품 원칙

1. 지원하지 않는 XMP 항목을 조용히 버리지 않고 사용자에게 알린다.
2. 내장 프리셋과 가져온 원본 XMP는 비파괴 방식으로 보존한다.
3. Lightroom 호환 색 설정과 LUME 전용 렌즈 효과를 분리한다.
4. Digital ND는 광학 ND로 표현하지 않는다.
5. 미리보기, 사진, 영상은 가능한 한 동일한 색 처리 순서와 수치를 사용한다.
6. Lightroom Mobile의 정보 구조는 참고하되 화면·아이콘·브랜드를 복제하지 않는다.

## 색 처리 파이프라인

```text
카메라 프레임
  → Lightroom 호환 LOOK
  → LUME LENS 효과 스택
  → Digital ND
  → 화면 프리뷰 / 사진 렌더링 / 영상 인코딩
```

처리 순서는 고정한다. LOOK은 톤과 색을 결정하고, LENS는 하이라이트와 광학적 분위기를 추가하며, ND는 최종 노출 감산 효과로 처리한다. 사용자는 각 단계 전체를 켜고 끌 수 있다.

## 트렌드 내장 룩

기존의 일반적인 골든아워·느와르 중심 구성을 다음 10종으로 교체한다.

1. 청량 에어리: 맑은 시안 블루, 깨끗한 흰색, 밝은 피부, 싱그러운 녹색
2. 핀터 에디토리얼: 크리미 베이지, 세이지 그린, 매트 블랙, 낮은 채도
3. 콰이어트 럭셔리: 아이보리, 월넛 브라운, 올리브, 부드럽고 깊은 명암
4. 쿨 아날로그: 시안 그림자, 따뜻한 피부, 부드러운 하이라이트
5. 코튼 스킨: 피부의 빨강·주황을 안정화하고 밝은 중간톤을 유지
6. 제주 블루: 하늘·바다의 시안과 블루를 분리하고 녹색의 노랑을 억제
7. 서울 나이트: 네온 마젠타·시안과 검은색을 유지하는 야간 룩
8. 크림 카페: 따뜻한 실내광, 크림색 흰색, 브라운 중심의 카페 룩
9. 플래시 다이어리: 직접 플래시 같은 밝은 피부와 선명한 원색
10. 빈티지 디카: 2000년대 콤팩트 카메라풍 채도, 차가운 그림자, 약한 페이드

각 룩은 XMP 호환 전역 보정값만 사용해 정의한다. 사용자가 값을 수정하면 내장 객체를 바꾸지 않고 새로운 사용자 프리셋을 만든다.

## 렌즈 필터

### Black Mist

- 강도 프리셋: 1/8, 1/4, 1/2
- 밝은 영역을 추출해 다중 패스 블러 후 원본에 합성한다.
- 검은색 대비는 최대한 유지하고 하이라이트 주변에만 글로우를 만든다.

### White Mist

- 강도 프리셋: 1/8, 1/4, 1/2
- 하이라이트 글로우와 함께 검은색을 들어 올리고 전체 대비를 낮춘다.
- Black Mist보다 넓고 밝은 확산 반경을 사용한다.

### Cross

- 형태: 4X, 6X, 8X
- 조절값: 강도, 빛살 길이, 회전 각도
- 설정한 임계값 이상의 점광원에만 방향성 블러를 적용한다.
- 점광원이 없는 장면에서는 효과가 거의 보이지 않는 것이 정상이다.

### 색상 필터

- Amber, Rose, Cyan, Blue, Green, Lavender, Tobacco, Sunset
- 각 필터는 색상, 농도, 중립점 보호값을 가진다.
- 단순 화면 오버레이가 아니라 휘도 보존형 색 혼합을 사용해 검은색과 피부가 쉽게 오염되지 않게 한다.

### Digital ND

- ND2: 1스톱
- ND4: 2스톱
- ND8: 3스톱
- ND16: 4스톱
- 화면과 결과물의 선형 밝기를 감산한다.
- UI에 `창작용 디지털 효과이며 광학 ND가 아닙니다`를 표시한다.
- 날아간 하이라이트 복구, 실제 장노출, 실제 모션 블러를 지원한다고 표현하지 않는다.

## 필터 스택 모델

한 프리셋은 Lightroom 호환 색 설정과 LUME 전용 설정을 함께 가진다.

```js
{
  id,
  name,
  source,
  xmpOriginal,
  xmpCompatibility: {
    supported: [],
    unsupported: [],
    warnings: []
  },
  basic,
  curve,
  hsl,
  grade,
  fx,
  lume: {
    schemaVersion: 1,
    lens: [
      { type: "blackMist", strength: 0.25 },
      { type: "color", id: "amber", amount: 0.15 }
    ],
    digitalNdStops: 0
  },
  version: 1,
  parentId: null,
  createdAt,
  updatedAt
}
```

첫 버전에서는 성능과 예측 가능성을 위해 미스트 또는 크로스 효과는 한 번에 하나만 활성화한다. 색상 필터는 하나를 추가할 수 있다. 따라서 최대 스택은 광학 효과 1개 + 색상 필터 1개 + Digital ND다.

## XMP 호환성과 저장

### 가져오기

1. XML 문법과 Camera Raw 네임스페이스를 검사한다.
2. 지원 필드, 미지원 필드, 파싱 경고를 분류한다.
3. 원본 XMP 문자열을 수정하지 않고 보존한다.
4. 미지원 항목이 있으면 개수와 대표 항목을 표시한 뒤 지원 필드만 적용한다.

### 앱 내부 저장

- IndexedDB를 우선 사용하고 localStorage는 마이그레이션 및 비상 폴백으로 사용한다.
- 원본, 수정본, 자식 버전 관계를 저장한다.
- 새로고침과 앱 재실행 후에도 현재 룩과 사용자 프리셋이 유지된다.

### XMP 내보내기

- Lightroom 호환 색 설정만 표준 Camera Raw XMP로 직렬화한다.
- LUME 렌즈 필터와 Digital ND는 `lume:` 전용 메타데이터 또는 앱 내부 JSON으로 보존한다.
- 내보내기 전에 `Lightroom에서는 LUME 렌즈 효과와 Digital ND가 제외됩니다`를 표시한다.
- 내보낸 XMP를 다시 파싱해 지원 필드가 원본 프리셋 객체와 일치하는지 검사한다.

## 모바일 UI

촬영 화면 하단에는 세 모드만 표시한다.

```text
[ LOOK ]  [ LENS ]  [ ND ]
```

- LOOK: 트렌드 및 사용자 프리셋 가로 목록
- LENS: Mist, Cross, Color 하위 카테고리
- ND: Off, ND2, ND4, ND8, ND16
- 활성 효과는 셔터 위 작은 칩으로 표시한다.
- 칩을 누르면 강도 조절과 제거 메뉴가 열린다.
- 길게 누르는 동안 전체 효과를 끄고 원본을 보여준다.
- `나만의 룩 저장`은 현재 LOOK, LENS, ND 조합을 하나의 사용자 프리셋으로 저장한다.

편집 화면은 변경된 항목에 점 표시를 하고, 저장 시 `덮어쓰기`와 `새 프리셋`을 구분한다. 내장 프리셋에는 덮어쓰기를 제공하지 않는다.

## 오류 처리

- XML 문법 오류: 파일명과 함께 `올바른 XMP 파일이 아닙니다` 표시
- 지원 항목 없음: 가져오기를 중단하고 이유 표시
- 일부 미지원: 지원 부분을 적용하고 경고 패널 제공
- WebGL 자원 부족: 고비용 필터를 자동 비활성화하고 LOOK만 유지
- 영상 녹화 중 필터 변경 실패: 기존 필터로 녹화를 계속하고 메시지 표시
- 저장소 용량 부족: 내보내기를 유도하고 데이터 손실 가능성을 알림

## 성능 정책

- 실시간 프리뷰는 기기 성능에 따라 렌더링 해상도를 조절한다.
- 미스트 블러는 축소 버퍼에서 처리한 뒤 업샘플링한다.
- 크로스 필터는 밝은 픽셀 임계값을 먼저 적용해 비용을 제한한다.
- 필터 변경 중에도 카메라 스트림을 다시 열지 않는다.
- 목표는 중급 Android 기기에서 1080p 프리뷰 30fps다.
- 웹 단계의 영상 최대 품질은 브라우저가 허용하는 범위이며 네이티브 최대 스펙을 약속하지 않는다.

## 테스트와 완료 기준

### 자동 테스트

- XMP 가져오기 → 수정 → 직렬화 → 재파싱 후 지원 값 일치
- 내장 프리셋 수정 시 원본 불변
- 새 프리셋과 덮어쓰기 동작 구분
- 지원하지 않는 XMP 필드가 경고 목록에 포함
- 렌즈 필터 스택 정규화와 최대 개수 제한
- Digital ND 스톱별 선형 감산값 계산
- 저장 후 재로딩 시 프리셋과 활성 조합 복원

### 시각 테스트

- 동일 기준 이미지로 트렌드 룩 10종 비교
- 미스트 강도 1/8, 1/4, 1/2가 순차적으로 증가
- Cross가 어두운 장면에서는 나타나지 않고 점광원에서만 나타남
- 색상 필터가 피부와 검은색을 과도하게 오염시키지 않음
- 원본 비교 동작이 모든 모드에서 즉시 반응

### 모바일 검증

- `https://loadguess-cyber.github.io/lume-camera/`에서 실행
- Android Chrome 카메라 권한 허용 후 실시간 효과 확인
- 사진과 영상에 같은 조합 저장
- 사용자 프리셋 저장 후 새로고침해도 유지
- XMP 다운로드 후 Lightroom Mobile 가져오기 확인
- 콘솔 오류 없이 편집, 저장, 삭제, 재가져오기 수행

## 네이티브 전환 기준

웹 검증에서 트렌드 룩과 편집 UX가 승인되면 Kotlin, CameraX, CameraEffect/SurfaceProcessor 기반으로 전환한다. 그 단계에서 최대 JPEG, 4K 영상, 10-bit HDR 가능 여부를 기기별로 조회하고, Computational ND는 별도 기능으로 설계한다.
